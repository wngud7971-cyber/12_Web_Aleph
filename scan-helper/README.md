# 스캔랩 — DB 설치 없이 두 스캔 방식을 직접 측정하기

DB를 배우는 학생이 예시 또는 자신의 공개·예시 CSV에서 찾을 조건을 정하고, 두 스캔 방식을 실제 실행해 시간 차이와 변동을 설명하도록 돕는 앱입니다.

기반 논문: **선택도에 따른 인덱스 스캔과 순차 스캔의 성능 비교** (배주형, 2026.10.02).

## 완료 상태

앱 구현과 실제 브라우저 기능 테스트를 완료한 실행 묶음입니다. 2026년 10월 12일 기능을 확인했고, 10월 13일 완성 ZIP을 다른 새 폴더에 풀어 실행.cmd로 다시 열리는 것을 확인했습니다.

| 완료한 확인 | 실제 확인 내용 |
|---|---|
| 예시 표 측정 | 200행 중 서울 66행, 각 방식 10회 실제 실행과 보고서 저장 |
| 혼합 CSV | 숫자·문자열·기호가 있는 600행·7열 전체 측정 |
| 2MB 초과 CSV | 8,356,571바이트, 3만 행·7열 전체 DB 가져오기와 반복 측정 |
| 최대 행·열 예시 | 205,055,368바이트, 100만 행·30열 전체 DB 가져오기와 반복 측정 |
| 비용·기록·그래프 | 조회 횟수 변경에 따른 계산, 별도 기록 누적, 기록 CSV와 SVG 저장 |
| SQL | 쿼리 복사·저장, 600행 및 3만 행 전체 SQL 다운로드, 실제 DB 실행 확인 |
| 잘못된 입력·취소 | 잘못된 CSV, 0행 조건, 조회 횟수 0, SQL 자료형 오류·중복 이름 안내와 정상 입력 복귀, 취소 후 재측정 |
| 실행 ZIP | 비밀번호 없이 새 폴더에 압축 해제 후 README의 실행.cmd로 정상 실행 |

테스트 환경은 Windows의 Codex 내장 Chromium, PGlite 0.5.8, PostgreSQL 18.3입니다. 실제 측정값·화면·저장 파일과 확인 범위는 ZIP의 `테스트기록/테스트결과.md`에 보관했습니다. 결과 시간은 해당 데이터와 환경에서의 관찰입니다.

## 다운로드한 앱 실행

1. 비밀번호 없는 ZIP을 새 폴더에 **전체 압축 해제**합니다.
2. Windows에서 압축을 푼 폴더의 **실행.cmd**를 두 번 클릭합니다. 현재 Windows 사용자 권한으로 실행하며 DB·Node·Python·추가 프로그램 설치가 필요 없습니다.
3. 기본 브라우저에 앱이 열립니다. 최신 Chrome·Edge를 권장합니다. 열리지 않으면 실행 창에 나온 `http://127.0.0.1:포트번호/` 주소를 브라우저에 넣습니다.
4. 사용하는 동안 실행 창을 열어 둡니다. 종료할 때 Ctrl+C를 누르거나 창을 닫습니다.

HTML 파일을 직접 열면 파일 탐색과 가상 결과 체험은 가능하지만 브라우저의 파일 접근 제한 때문에 내장 측정은 실행.cmd로 열어야 합니다. 현재 결과물은 로그인 없이 로컬에서 실행되는 ZIP입니다. 공개 사이트로 배포하면 주소를 여는 것만으로 사용할 수 있습니다. 포트폴리오 연결 상태는 ZIP의 제출 안내에서 별도로 관리합니다.

macOS·Linux에서 Python 3가 이미 있다면 `scan-helper` 폴더에서 `python3 -m http.server 8000 --bind 127.0.0.1`을 실행하고 `http://127.0.0.1:8000/`을 엽니다. DB 설치는 필요 없습니다. Windows 실행.cmd는 macOS·Linux용 실행 파일이 아닙니다.

## 사용자가 하는 세 가지 일

1. **데이터와 조건 선택:** 예시로 바로 측정하거나 CSV를 선택하고 찾을 컬럼·값을 정합니다.
2. **실제 측정과 비교:** `3. 시간 측정하고 비교하기`을 누르고 진행률을 확인합니다. 결과는 자동 표시됩니다.
3. **설명과 기록:** 어느 방법이 빠른지 또는 차이가 불분명한지 읽고 `보고서 저장`을 누릅니다.

## 처음이라면

첫 화면에서 **예시로 먼저 체험하기**를 누릅니다. 앱이 가상 주문 CSV 200행에서 지역이 서울인 66행을 두 방법으로 실제 조회합니다. 데이터는 가상이지만 실행 시간은 실제 측정값입니다. 200행은 작은 표이므로 차이가 아주 작거나 불분명할 수 있으며, 큰 테이블의 성능을 예측하는 자료가 아닙니다.

첫 실행에는 동봉된 측정 엔진 초기화 시간이 걸립니다. 준비 → 가져오기 → 인덱스 준비 → 반복 측정 → 자동 비교 순으로 표시되며 `측정 취소`로 중단할 수 있습니다. 진행률은 단계 기준으로 남은 시간을 예측하지 않습니다.

## 필요한 기능만 펼쳐 보기

처음에는 ‘예시로 먼저 체험하기’ 또는 ‘내 CSV로 측정하기’ 두 버튼에서 시작합니다. 표 선택 화면은 찾을 열·값·실제 조회 행 수·측정 시작이 중심이며, 파일 형식·표 미리보기·자료형 수정은 필요할 때 펼칩니다.

결과 화면에서는 판정과 두 평균을 먼저 읽습니다. 숫자가 작을수록 조회 시간이 짧습니다. 평균이 짧아도 실행 변동에 비해 차이가 작으면 ‘우위 불분명’으로 표시합니다. ‘찾을 값을 바꿔 다시 측정’은 같은 CSV를 유지하며 데이터 선택 단계로 돌아갑니다.

- ‘누적 기록·그래프 보기’: 누적 실험 기록 메뉴를 열고 해당 위치로 이동합니다. 모든 개별 기록은 ‘모든 기록을 표로 보기’에서 확인합니다.
- ‘SQL 가져가기’: SQL 메뉴를 열고 해당 위치로 이동합니다. 데이터까지 필요하면 ‘CSV 전체 SQL 저장’, 조회 코드만 필요하면 ‘조회·측정 쿼리 보기 / 복사’를 사용합니다.
- ‘인덱스 생성 비용’: 결과 아래의 메뉴를 펼쳐 생성 비용·참고 회수 횟수를 확인합니다.
- ‘측정 원본·실행 계획 자세히 보기’: 자동 측정 원본 입력을 펼쳐 확인합니다. 값을 수정하면 기존 실제 측정의 비용 표시를 제거하고 수정값을 다시 비교합니다.

큰 코드·기록 표·추가 계산은 기본으로 접혀 있습니다. 단계가 바뀌면 추가 기능 메뉴를 접어 현재 할 일에 집중하도록 합니다. 기록은 계속 누적되지만 데이터 선택·측정 진행 중에는 기록 화면을 숨깁니다. 새로고침하면 사라지므로 필요한 기록을 저장하세요.

## 내 CSV로 측정

1. `내 CSV로 측정하기` → 공개·예시 CSV 파일 선택.
2. 전체 파일 확인 후 찾을 컬럼과 값을 선택합니다. 숫자·문자열·기호가 서로 다른 컬럼에 함께 있어도 됩니다. 미리보기는 처음 5행입니다.
3. `지금 할 실험`에 전체 행 수와 실제 조회 행 수가 나오는지 확인합니다.
4. `3. 시간 측정하고 비교하기`을 누릅니다. PostgreSQL 설치나 SQL 복사·결과 파일 전달이 필요 없습니다.
5. 앱이 측정을 마치면 두 평균·표준편차·논문의 판정 방법을 적용한 결과를 표시합니다. `보고서 저장`으로 기록합니다.

지원 입력 범위: UTF-8·첫 줄 제목·쉼표/탭/세미콜론, 최대 500MiB(524,288,000바이트)·100만 행·30컬럼·셀당 2,000자. INTEGER·NUMERIC·TEXT를 사용하며 선행 0과 혼합 값은 TEXT로 제안합니다. 빈 필드는 NULL, 따옴표로 감싼 빈 문자열은 문자열로 유지합니다. 전체 행을 확인하고 자료형을 변경한 경우 호환성을 검증합니다. 긴 인덱스 값과 잘못된 입력은 수정 안내를 표시합니다.

목록은 처음 발견한 서로 다른 값 최대 100개이며 각 행 수는 전체 파일에서 센 값입니다. 목록 밖의 값을 직접 넣으면 전체 파일에서 다시 셉니다. CSV를 복제하거나 일부 행만 측정한 값을 전체 측정으로 표시하지 않습니다.

## 인덱스 생성 비용과 조회 효과

실제 측정 결과 아래에서 인덱스 생성 시간(1회), 인덱스 크기, 인덱스를 제외한 표 저장 공간을 확인합니다. 크기 확인에 실패해도 조회 측정은 계속하며 크기는 미확인으로 표시합니다.

- 생성 시간: Worker의 CREATE INDEX 요청부터 완료까지 경과 시간. CSV 가져오기·ANALYZE·크기 확인을 제외합니다. 조회는 PostgreSQL Execution Time을 사용하므로 두 시간의 합계는 단순 참고 계산입니다.
- 논문의 탐색적 기준으로 인덱스가 우위인 경우에만 `ceil(생성 시간 / 조회당 평균 절약 시간)`을 참고 회수 횟수로 표시합니다. 차이가 불분명하거나 인덱스가 느리면 회수 횟수를 제시하지 않습니다.
- 예상 조회 횟수(1~10억 정수)를 바꾸면 `순차 평균 × 횟수`와 `생성 시간 + 인덱스 평균 × 횟수`를 비교합니다. 실제로 그 횟수만큼 실행하는 기능은 아닙니다.
- 동일 조회의 시간 차이가 계속 유지되는 가정입니다. 데이터 수정·인덱스 유지·통계 준비·가져오기·통신·화면 표시 비용은 제외합니다. 생성 시간은 한 번의 관찰이며 다른 서버의 비용이나 논문에서 검증한 회수 기준이 아닙니다.
- 보고서·기록 CSV에도 생성 시간·크기·참고 회수 횟수가 포함됩니다. 비교 입력을 직접 바꾸면 기존 측정의 비용 표시를 제거합니다.

짧은 확인: 예시 실제 측정 완료 → 결과의 생성 비용 카드 확인 → 예상 조회 횟수를 10, 100으로 바꿔 합계 확인 → 문자·0·음수를 넣으면 수정 안내가 나오는지 확인. 어느 방법이 우위인지는 실제 측정에 따라 달라집니다.

크기는 [PostgreSQL 저장 공간 함수](https://www.postgresql.org/docs/18/functions-admin.html#FUNCTIONS-ADMIN-DBSIZE)의 pg_relation_size(인덱스)·pg_table_size(표)를 사용합니다. DB 내부 바이트 수이며 브라우저 전체 메모리나 앱 다운로드 크기가 아닙니다.

## 실험 기록 비교

앱에서 CSV 측정이 완료되면 결과 아래 `누적 실험 기록과 그래프 보기`에 자동으로 추가됩니다. 메뉴를 펼쳐 확인합니다. `현재 CSV 조건 바꿔 다시 측정`을 눌러 같은 CSV의 다른 값을 선택하고 다시 측정하면 두 결과가 나란히 쌓입니다. 예시 200행은 지역/서울 66행(33%)과 지역/부산 67행(33.5%)을 비교할 수 있습니다. 큰 가상 주문 CSV는 배송지역/서울 10만 행(10%)과 배송지역/부산 18만 행(18%)을 비교할 수 있습니다.

- 비교 표: 조건, SQL 컬럼과 자료형, 실제 전체·조회 행 수, 조회 비율, 방식별 반복 횟수, 두 평균 실행 시간, 판정, D·2SE.
- CSV 선택마다 새 묶음을 만들며 파일명·파일 크기·행 수가 같다는 이유로 합치지 않습니다. 같은 파일을 다시 골라도 새 묶음입니다.
- 같은 CSV의 테이블 자료형 설정 또는 엔진 버전이 바뀐 기록은 별도 묶음으로 표시합니다. 조회 컬럼이 다른 기록은 표에 컬럼을 표시하며 다른 조건의 실험으로 해석합니다.
- 각 측정 완료를 별도 행으로 저장합니다. 같은 조건을 다시 측정한 값도 합산하지 않습니다. 가상 시간 체험·직접 수정한 비교 입력·실패·취소는 자동 기록하지 않습니다.
- 최근 100개를 브라우저 메모리에 보관하며 초과하면 가장 오래된 기록을 제거합니다. 개별 삭제와 전체 비우기가 있습니다. 새로고침·창 닫기 후에는 사라집니다.
- `이 묶음의 기록 CSV 저장`으로 현재 묶음의 숫자 결과·판정·버전을 보관합니다. 원본 파일명·컬럼 제목·조회값·실행 계획 필터·개인 환경 메모는 이 파일에 넣지 않습니다. 화면의 조회 조건은 현재 브라우저 메모리에서만 표시합니다.

기록은 조건별 관찰 결과입니다. 부하·캐시·조회 컬럼·반복 횟수 등에 따라 달라질 수 있으므로 선택도만으로 차이의 원인이나 성능 역전 지점을 단정하지 않습니다. 각 행의 판정은 해당 측정에서 개별 계산합니다.

짧은 확인: 서울 측정 완료 → 현재 CSV 조건 바꾸기 → 부산 선택 → 측정 완료. 같은 묶음에 다른 조건 2행이 있어야 하고, 원래 결과를 다시 확인해도 중복 행이 생기지 않아야 합니다. 자료형을 바꾸거나 다른 CSV를 선택하면 묶음이 분리되어야 합니다. 기록 파일에서 실제 조회값과 원본 파일명이 빠졌는지 확인합니다.

### 기록 그래프

‘누적 실험 기록과 그래프 보기’를 펼치면 그래프는 같은 CSV·자료형·엔진 설정 안에서 **동일 조회 컬럼**의 기록을 보여 줍니다. 가로축은 실제 조회 행 비율(0~100%), 세로축은 평균 실행 시간(ms)입니다. 점은 개별 기록의 평균이며 같은 비율의 반복 기록도 합치지 않습니다. 세로 막대는 평균 ± 표본 표준편차(0 아래는 자름)로 신뢰구간이나 우위 경계가 아닙니다.

컬럼 선택으로 다른 컬럼의 기록을 분리해 봅니다. 점을 누르거나 Enter·Space로 선택하거나 ‘상세 결과를 볼 기록’에서 고르면 조건·횟수·판정을 확인할 수 있습니다. 같은 위치의 점은 겹칠 수 있어 목록과 표에서도 확인합니다. 그래프를 SVG로 저장하면 원본 파일명·컬럼 제목·조회값을 제외한 그래프를 보관합니다. 점을 잇거나 미측정 선택도를 보간하지 않으며 그래프만으로 원인·역전 지점을 확정하지 않습니다.

짧은 확인: 같은 CSV에서 서울·부산을 측정 → 해당 컬럼의 그래프에 두 기록 확인 → 상세 기록을 바꾸면 표와 같은 평균·횟수 표시 → 다른 컬럼을 측정하면 컬럼 선택으로 분리 → SVG 저장 확인.

## 쿼리 복사와 CSV → SQL 변환

CSV를 고르면 아래에 `CSV를 SQL로 변환하거나 쿼리 가져가기` 메뉴가 나타납니다. 메뉴를 펼쳐 사용합니다. 데이터 선택·측정 진행·결과 화면에서 계속 사용할 수 있습니다.

- `표 만들기`, `데이터 가져오기`, `인덱스 만들기`, `조회하기`, `순차 스캔`, `인덱스 스캔` 중 선택해 **현재 쿼리 복사** 또는 **현재 쿼리 .sql 저장**을 누릅니다. 데이터 가져오기는 앱 전용 가상 파일의 COPY문이며 외부 DB에서 그대로 실행하지 않습니다. 외부 DB에 넣을 실제 데이터는 CSV 전체 SQL 저장의 INSERT문을 사용합니다.
- 측정 중에는 현재 단계의 쿼리를 따라 표시합니다. 다른 쿼리를 직접 선택하면 따라보기를 끄고 고른 쿼리를 유지합니다.
- 표시하는 조회 쿼리는 현재 조회값을 안전하게 넣은 외부 PostgreSQL용 SQL입니다. 앱 내부는 같은 조건을 매개변수로 전달합니다. 복사한 스캔 쿼리는 한 번의 EXPLAIN 실행 예이며 반복 측정 전체 기록이 아닙니다.
- **CSV 전체 SQL 저장**은 실제 모든 행을 INSERT문으로 변환하고 테이블 생성문과 함께 `scanlab-data.sql`에 넣습니다. 쿼리 저장 버튼은 데이터 전체 저장과 별개입니다.
- `SQL 저장 설정`을 열어 테이블 이름·각 컬럼 이름·자료형을 확인·수정합니다. 기본값은 임시 scanlab_practice와 순서대로 c_1, c_2…입니다. `CSV 제목을 컬럼명으로 사용`은 중복·빈·너무 긴 제목을 정리한 이름을 제안하며 저장 전에 확인할 수 있습니다.
- 이름은 UTF-8 63바이트 이내이고 중복·빈 이름·제어 문자는 수정 안내가 나옵니다. 한글·공백·예약어·따옴표도 안전한 SQL 식별자로 감쌉니다. 앱이 추가하는 행 번호 scanlab_row_id는 컬럼명으로 사용할 수 없습니다.
- SQL 자료형은 전체 CSV와 맞아야 합니다. NULL·빈 문자열·한글·기호·따옴표·백슬래시를 보존합니다. 앞자리 0인 식별자는 TEXT로 보존하며 숫자로 바꾸면 숫자 표기를 정규화합니다. 큰 CSV에서는 메타데이터로 사전 검증하고 변환 중에도 모든 값을 검증합니다.
- 저장 설정은 외부 DB용 전체 SQL·표 생성·인덱스·조회·스캔 쿼리에 일관되게 적용합니다. 앱 내부 측정은 1단계 자료형과 c_1, c_2…를 사용하며, 데이터 가져오기 탭은 앱 전용 COPY문입니다. 저장 설정은 측정 결과나 실제 앱 DB를 바꾸지 않습니다. `이름 기본값 / 현재 측정 자료형 가져오기`로 최신 측정 설정을 다시 가져올 수 있습니다.
- 기본 임시 표는 새 연결에서 전체 SQL을 먼저 실행하고 **같은 연결**에서 조회합니다. 일반 표를 선택하면 public 스키마에 계속 보관합니다. 기존 표가 있으면 생성 오류로 트랜잭션을 중단하며 덮어쓰거나 DROP하지 않습니다. 일반 표 실행에는 public 스키마의 생성 권한이 필요합니다.
- 이름·자료형을 바꾸면 전체 SQL과 조회 쿼리를 함께 다시 저장합니다. 변환 중 설정을 바꾸면 이전 변환을 취소합니다.

작은 SQL은 일반 다운로드로 저장합니다. 보수적으로 추산한 SQL 크기가 64MiB를 넘고 직접 저장을 지원하는 브라우저라면 저장 위치를 선택해 작은 묶음으로 기록합니다. 큰 SQL은 파일을 한꺼번에 메모리에 만들지 않고 작은 묶음으로 저장합니다. Chrome·Edge의 직접 파일 저장을 사용할 수 있는 공개 HTTPS 주소 또는 실행.cmd의 로컬 주소에서 저장 위치를 선택합니다. 이 기능을 지원하지 않는 브라우저는 생성 SQL 64MiB까지 일반 다운로드로 제공합니다. 한도를 넘으면 수정 안내가 나오며 일부 행만 완료 파일로 제공하지 않습니다. 취소·오류 시 열린 저장 작업을 중단합니다. SQL 파일에는 원본 데이터 값이 포함되므로 공유 전 공개·예시 데이터인지 확인하세요.

이전 기본 이름 형식으로 약 205MB의 가상 주문 CSV를 전체 변환해 100만 행·30컬럼, 약 286MB의 INSERT 출력을 확인했습니다. 최신 출력 크기는 이름·자료형 설정에 따라 달라집니다. 큰 파일 변환은 순서대로 작은 출력 묶음을 전달하는 방식이며 전체 출력은 메모리에 모으지 않습니다. 이 확인은 변환 함수의 출력 검증입니다. 최신 버전에서는 브라우저의 쿼리 복사·쿼리 다운로드와 600행·3만 행 전체 SQL 다운로드를 확인했습니다. 내려받은 전체 SQL은 실제 PGlite에 실행해 행 수와 값 보존을 확인했습니다. 100만 행 CSV의 전체 SQL을 Windows 저장 위치 선택창에서 끝까지 저장하는 항목은 이번 검증 범위에 포함하지 않았습니다.

공식 참고: [파일 저장 선택](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker), [나눠 쓰기](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemWritableFileStream/write).

## 브라우저 측정의 의미와 범위

PGlite **0.5.8**을 동봉했습니다. PostgreSQL을 WebAssembly로 실행하며, JavaScript 배열 검색 시간을 DB 시간으로 대신 쓰지 않습니다. 선택한 CSV 전체를 작은 묶음으로 임시 메모리 DB에 가져오고 인덱스를 만든 뒤 `EXPLAIN (ANALYZE, BUFFERS, TIMING OFF, FORMAT JSON) SELECT * ...`로 실행 시간을 읽습니다.

- 가져오기·인덱스 생성·화면 표시 시간은 스캔 시간에 포함하지 않습니다.
- 비병렬·JIT 끔·비트맵/인덱스 온리 끔으로 각 방식을 유도합니다.
- 각 방식 준비 실행 1회는 제외하고 두 방식을 번갈아 5·10·30회 실행합니다.
- DB에서 전체/조회 행 수를 다시 세고, 매 실행 계획의 실제 스캔 방식과 행 수를 확인합니다. 다른 계획이면 비교를 중단합니다.
- 결과는 **이 CSV·이 브라우저 내 메모리 DB 환경**의 측정입니다. 논문의 일반 PostgreSQL 환경이나 운영 서버 성능을 재현·예측하지 않습니다. PC·브라우저·부하·캐시에 따라 달라집니다.

입력 범위 안의 대용량 파일도 실행 가능 여부와 시간은 PC의 여유 메모리에 따라 달라집니다. 205MB 예시 CSV의 전체 읽기·집계, 100만 행·30열 전체 DB 가져오기, 서울 10만 행을 각 방식 10회 실제 조회하는 과정을 완료했습니다. 원본 실행 시간과 화면은 테스트기록 폴더에 보관했습니다. 메모리 부족 또는 오류가 나면 안내하며 데이터를 줄여 다시 시도할 수 있습니다. 중단 시 측정 Worker를 종료하고 해당 메모리 DB를 버립니다. 완료 시 DB를 닫고 Worker를 종료합니다.

## 다른 시작 방식

첫 화면의 접힌 상세 메뉴에 가상 시간으로 결과 읽기 연습, 논문 공개 요약 결과, 외부 PostgreSQL용 큰 예시 SQL, 이미 가진 측정값 비교가 있습니다. 가상 시간 예시는 실제 측정과 구분해 표시합니다. 큰 예시 SQL과 CSV 고급 설정의 외부 DB용 SQL은 일반 PostgreSQL에서 직접 측정하려는 사용자를 위한 추가 기능입니다.

외부 CSV SQL은 작은 파일의 준비·측정·결과를 같은 DB 연결에서 실행합니다. 2MiB 또는 1만 행을 넘는 CSV는 화면의 안내대로 `scanlab-input.csv`와 `scanlab-my-csv-experiment.sql`을 같은 폴더에 저장하고 `psql -X -U DB사용자 -d 학습DB -f scanlab-my-csv-experiment.sql`을 실행합니다. 자신의 DB 이름·사용자로 바꿉니다. 비밀번호를 명령에 쓰지 않습니다. 생성된 `scanlab-seq.json`과 `scanlab-index.json`은 비교 화면의 각 결과 파일 선택으로 넣습니다. 같은 이름의 이전 결과는 덮어씁니다. 이 추가 경로만 외부 PostgreSQL이 필요합니다.

공식 참고: [PGlite](https://pglite.dev/docs/about), [PGlite API](https://pglite.dev/docs/api), [psql](https://www.postgresql.org/docs/18/app-psql.html).

## 논문이 실제로 쓰이는 부분

논문에서 앱이 될 문장:

> DB를 배우는 학생이 인덱스·순차 스캔 실습 결과를 해석할 때, 이 앱은 선택도만으로 우위를 단정하지 않는 논문의 결과와 평균 차이·변동을 함께 보는 판정 방법을 적용해 비교 결과와 추가 측정 방향을 알려 줍니다.

- 논문 표 3: 선택도 0.1~100%의 15개 구간. 각 방식 10회.
- 논문 표 6: 80% 추가 측정. 각 방식 30회. 원 실험과 합치지 않음.
- 탐색 화면은 **반올림된 공개 요약 통계와 논문에 적힌 판정**을 사용합니다. 원자료를 복원하거나 해당 실행 시간을 다른 환경의 예측으로 사용하지 않습니다.
- 내 측정 화면은 입력으로부터 평균과 표본분산을 직접 계산합니다.

```
D = 순차 평균 − 일반 인덱스 평균
SE = sqrt(순차 표본분산 / 순차 횟수 + 인덱스 표본분산 / 인덱스 횟수)
D > 2SE: 일반 인덱스 우위
D < -2SE: 순차 스캔 우위
나머지: 우위 불분명
```

논문의 탐색적 기준입니다. 정식 유의성 검정·95% 신뢰구간이 아닙니다. 각 방식 2~500회, 0~1,000,000,000ms 범위를 지원하며 반복 횟수가 적거나 변동이 0이면 확인할 점을 표시합니다. 선택도 입력은 실험 맥락을 남기는 용도이며 성능 판정이나 예측에 사용하지 않습니다. 동일 조건 확인을 하지 않으면 결과에 확인 필요 표시가 붙습니다.

## JSON 입력 범위

`EXPLAIN (ANALYZE, BUFFERS, TIMING OFF, FORMAT JSON) SELECT ...`의 **JSON 결과만** 넣습니다. ANALYZE는 쿼리를 실제 실행하므로 학습용 SELECT를 사용하세요.

- JSON 배열 안에 여러 실행을 넣거나, 각 실행의 JSON을 줄바꿈으로 이어 붙일 수 있습니다.
- 각 실행의 최상위 `Execution Time`을 ms로 읽습니다. 비용 추정값과 개별 노드 시간을 실행 시간으로 사용하지 않습니다.
- 순차 칸에는 `Seq Scan`, 인덱스 칸에는 `Index Scan` 노드가 하나인 비병렬 실행 결과가 필요합니다.
- 조인·다중 스캔·병렬·비트맵·인덱스 온리는 범위 밖이므로 안내 메시지가 나옵니다.
- 버퍼 정보는 최상위 `Plan`의 `Shared Read Blocks`만 읽어 하위 노드와 중복 합산하지 않습니다. 이 지표로 물리 디스크 I/O나 캐시 효과의 원인을 단정하지 않습니다.

## 데이터와 비밀값

- 논문 데이터는 공개 요약 통계이며 학습 예시는 새로 만든 가상 데이터입니다. 예시는 논문 원자료와 구분해 표시합니다.
- CSV·측정값의 서버 전송과 분석 추적, 계정, API 키, 환경 변수는 사용하지 않습니다. 동봉된 PGlite 실행 파일은 앱과 같은 주소에서 읽습니다. 외부 CDN에 실행 파일을 요청하지 않습니다.
- 입력값은 브라우저 메모리에서만 처리합니다. 새로고침하면 사라집니다.
- 보고서에는 실행 시간·횟수·계산 근거만 포함합니다. JSON에 들어 있는 SQL, 관계명, 필터, 개인정보는 보고서에 옮기지 않습니다.
- 실제 응답자의 개인정보 대신 예시 데이터를 쓰세요.

## 파일 구성과 배포

실행.cmd와 start.ps1은 Windows에서 앱 파일을 **127.0.0.1의 임시 포트**로 제공하는 실행 도구입니다. 외부 주소에는 바인딩하지 않습니다. CSV를 서버로 전송하지 않으며 파일은 브라우저 Worker 내부에서 처리합니다. 동봉된 vendor/pglite 실행 파일과 라이선스를 유지하세요. 로그인·비밀번호·API 키·환경 변수는 없습니다.

공개 배포는 `scan-helper` 폴더 전체를 정적 사이트로 올립니다. JS·MJS는 JavaScript MIME, WASM은 application/wasm으로 제공해야 합니다. 폴더 위치가 달라도 상대 경로로 실행됩니다. 12번 포트폴리오에는 별도 앱 페이지의 링크와 누구를 어떻게 돕는지 한 문장을 대표작 자리에 넣습니다. 동료의 익명 감상은 ZIP의 동료_익명감상.txt와 제출문에 기록했습니다. 공개 배포·포트폴리오 연결은 제출 안내에 별도 항목으로 표시했습니다.

`engine-core.js`는 측정 설정 검증, `engine-worker.mjs`는 CSV 가져오기와 DB 반복 실행, `engine-ui.js`는 측정 진행과 취소, `app.js`는 자동 비교·보고서, `csv-stream.js`는 큰 CSV 나눠 읽기를 담당합니다. `history.js`·`history-ui.js`는 기록 검증·묶음·비교표·기록 파일 저장, `sql-export.js`·`sql-tools.js`는 쿼리 복사와 CSV 전체 SQL 변환을 담당합니다. 논문 공개 통계는 paper-data.js, 동봉 논문은 paper.html에 있습니다.
