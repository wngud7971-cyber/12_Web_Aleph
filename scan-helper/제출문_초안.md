# 13번 과제 제출문

결과물: 비밀번호 없는 실행 ZIP. 압축을 새 폴더에 모두 풀고 실행.cmd를 엽니다.
기반 논문: 선택도에 따른 인덱스 스캔과 순차 스캔의 성능 비교.

## 논문에서 앱으로 옮긴 문장
DB를 배우는 학생이 자신의 공개·예시 CSV로 인덱스 효과를 실험할 때, 이 앱은 DB 설치 없이 두 스캔 방식을 실제 실행하고 선택도만으로 우위를 단정하지 않는 논문의 결과와 평균 차이·변동을 함께 보는 방법으로 비교 결과와 추가 측정 방향을 알려 줍니다.

## 사용자가 할 일 세 가지
1. 예시 표 또는 예시CSV 폴더의 파일을 선택하고 찾을 열·값을 정합니다.
2. 시간 측정하고 비교하기를 눌러 두 방식의 평균·변동·판정을 읽습니다.
3. 조건을 바꿔 기록과 그래프를 비교하고 보고서·SQL·기록을 저장합니다.

## 짧은 확인 방법
- 실행.cmd: 새 폴더에서 앱을 열고 첫 화면의 논문 제목과 도움 설명을 확인합니다.
- 예시로 먼저 체험하기: 200행 중 서울 66행, 방식별 10회 결과가 나오면 통과입니다. 어느 방식이 빠른지는 고정하지 않습니다.
- 예시CSV/혼합표_600행.csv: 지역/서울을 선택하면 600행 중 120행을 조회합니다. 조건을 바꾸고 측정하면 별도 기록과 그래프 점이 생겨야 합니다.
- 보고서 저장, 기록 CSV 저장, 그래프 SVG 저장, 현재 쿼리 저장, CSV 전체 SQL 저장을 해 봅니다. 내려받은 SQL의 CREATE TABLE과 모든 행 INSERT, 실제 전체 행 수를 확인합니다.
- 오류_닫히지않은따옴표.csv, 조회 0행, 잘못된 SQL 자료형·중복 이름, 예상 조회 횟수 0에는 수정 안내가 나오고 정상 입력으로 다시 사용할 수 있어야 합니다.
- 기반 논문은 scan-helper/paper.html, 실행 안내는 scan-helper/README.md, 실제 확인 증거는 테스트기록/테스트결과.md에 있습니다.

## AI와 나의 판단 세 줄
① AI에게 맡긴 일: 논문의 판정 방법을 앱으로 구현하고 CSV 처리, 브라우저 DB 측정, SQL 변환·저장, 비용 계산, 기록·그래프, 입력 검증, 화면 구성, 실제 기능 테스트와 실행 ZIP 제작을 맡겼습니다.
② 내가 직접 판단한 일: DB를 배우는 학생을 대상으로 정하고 한 표에 숫자·문자열·기호를 함께 지원하도록 했습니다. DB 설치 없이 직접 측정하고 결과를 가져갈 수 있게 했으며, 화면이 복잡하다고 판단해 기본 흐름을 단순화하도록 요청했습니다. 보고서 디자인은 주황색으로 확정하고 동료 감상을 제공했습니다.
③ AI 제안을 따르지 않은 일: 유형별로 나누거나 한 TEXT 열의 혼합 값만 다루는 방향을 수정해 여러 자료형의 열이 함께 있는 표를 지원하도록 했습니다. 포트폴리오 연결에 앞서 앱을 완성하고 확인하는 순서를 정했습니다.

## 동료 한 사람의 감상
익명 동료 의견: “숙련된 사람에게는 큰 필요가 없을 수 있지만, DB에 능숙하지 않거나 처음 접하는 사람이 인덱스와 풀 스캔을 이해하는 데 도움이 될 수 있을 것 같다.”

## 외부 연결의 현재 상태
